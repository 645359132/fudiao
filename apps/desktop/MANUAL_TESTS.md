# 桌面应用手工测试清单

自动测试（`apps/desktop/src/ui/app.test.tsx`、`src/app/service.test.ts`）已用真实的用例与作品库覆盖界面流程。以下几项依赖真实窗口、系统对话框或文件系统，发布前在 Windows 上手工走一遍，并在“记录”中写下日期、版本与结果。

启动开发模式：

```bash
pnpm --filter @fudiao/desktop tauri dev
```

## M1-04 作品管理与章节目录

1. 首次启动显示“还没有作品”，作品库位置为“文档\复调”。
2. 新建作品“雨夜”：“文档\复调\雨夜”下出现 `project.sqlite`，进入作品界面，窗口标题为“复调”。
3. 再新建同名作品：文件夹为“雨夜（2）”。
4. “作品列表”返回后关闭并重新启动应用：两部作品仍在列表中，最近打开的在前。
5. “打开作品文件夹”：系统文件夹选择框打开；选择一个普通文件夹时提示“这个文件夹里没有作品”，且该文件夹中没有生成任何文件；选择“文档\复调\雨夜”时正常打开。
6. “更改位置”选择另一个磁盘上的文件夹，新建作品建在那里；原有作品不移动。
7. 归档与取消归档：作品移到“已归档”分组并可展开；文件夹不变。
8. 在资源管理器中删除一部作品的文件夹，回到作品列表：显示“找不到作品文件夹”，可以“从列表移除”。
9. 章节：新建三章，双击或按 F2 重命名，用鼠标拖动调整顺序，用“↑”“↓”调整顺序，删除到回收站后恢复；重新启动应用后顺序与回收站内容保持不变。
10. 键盘：Tab 可以依次到达章节与章节操作按钮，Esc 取消正在输入的章节名。
11. 中文输入法（微软拼音）在作品名、章节名、梗概与备注中组合输入正常，回车确认候选词时不会提前提交表单。

## M1-05 编辑器与自动保存

自动测试已覆盖：段落标识在拆分、合并、跨段删除、粘贴、移动、撤销重做下的继承（含随机编辑）；保存计划与版本守卫；自动保存的防抖、组合期间不保存、失败重试；草稿恢复；保存失败时复制与导出。以下依赖真实输入法与真实进程：

1. 输入法（微软拼音、搜狗拼音、五笔各一遍）：在段首、段尾、两段之间组合输入；组合中按回车选词，不应拆分段落；组合中状态栏不应出现“保存中”；组合结束约 1 秒后显示“已保存”。
2. 组合结束后按 Ctrl+Z、Ctrl+Y：撤销与重做以词为单位，文字与光标位置正确。
3. 连续输入一段长文字，停止后 2 秒内显示“已保存”（需求第八章“保存反馈”）。
4. 在段首回车插入空行、在段中回车拆分、在段首退格合并后切换章节再切回：文字与分段一致。
5. Ctrl+S 立即保存；状态栏的撤销、重做按钮可用。
6. 意外退出：输入一句后在 1 秒到 1.5 秒之间用任务管理器结束 `fudiao.exe`；重新打开作品与该章，显示“发现某时未保存的编辑”；“恢复这些编辑”后文字回来并自动保存；再次打开不再提示。“丢弃”后不再提示，文字为上次保存的内容。
7. 保存失败：打开作品后在资源管理器中把 `project.sqlite` 设为只读（或拔出作品所在的移动硬盘）；继续输入，状态栏显示“保存失败”与原因；“复制全文”后可粘贴到记事本；“导出本章”弹出保存对话框并写出 txt；此时切换章节被拦下并提示；关闭窗口第一次被拦下，第二次直接退出，重新打开后可从草稿恢复。
8. 粘贴从 Word 或网页复制的多段文字：按段落拆分，没有样式与图片。

## M1-06 章节快照

自动测试已覆盖：建立、列表、预览、恢复与再次恢复；恢复前快照；标识、顺序、版本、来源标记与事件关联；导出导入。以下在真实窗口中走一遍：

1. 写几段后“保存快照”，继续修改，打开“版本快照”：列表显示时间与“手动保存”，点击后右侧显示当时的正文、段数与字数。
2. “恢复到这个版本”→“确定恢复”：回到正文，内容为快照中的文字；列表新增一条“恢复前自动保存”，恢复它可以回到恢复前的文字。
3. 在输入法组合中途点“保存快照”：组合结束后才保存，快照内容包含组合结束后的文字。
4. 恢复后按 Ctrl+Z：撤销历史已清空，不会撤回到恢复前的内容（恢复前的内容在快照中）。
