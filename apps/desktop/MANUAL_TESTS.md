# 桌面应用手工测试清单

自动测试（`apps/desktop/src/ui/app.test.tsx`、`src/app/service.test.ts`）已用真实的用例与作品库覆盖界面流程。以下几项依赖真实窗口、系统对话框或文件系统，发布前在 Windows 上手工走一遍，并在“记录”中写下日期、版本与结果。

启动开发模式：

```bash
pnpm --filter @fudiao/desktop tauri dev
```

## M1-04 作品管理与章节目录

1. 首次启动显示“还没有作品”，作品库位置为“文档\复调”。
2. 新建作品“雨夜”：“文档\复调\雨夜”下出现 `project.sqlite`，进入作品界面，窗口标题为“复调”。
3. 再新建同名作品：文件夹为“雨夜（2）”。
4. “作品列表”返回后关闭并重新启动应用：两部作品仍在列表中，最近打开的在前。
5. “打开作品文件夹”：系统文件夹选择框打开；选择一个普通文件夹时提示“这个文件夹里没有作品”，且该文件夹中没有生成任何文件；选择“文档\复调\雨夜”时正常打开。
6. “更改位置”选择另一个磁盘上的文件夹，新建作品建在那里；原有作品不移动。
7. 归档与取消归档：作品移到“已归档”分组并可展开；文件夹不变。
8. 在资源管理器中删除一部作品的文件夹，回到作品列表：显示“找不到作品文件夹”，可以“从列表移除”。
9. 章节：新建三章，双击或按 F2 重命名，用鼠标拖动调整顺序，用“↑”“↓”调整顺序，删除到回收站后恢复；重新启动应用后顺序与回收站内容保持不变。
10. 键盘：Tab 可以依次到达章节与章节操作按钮，Esc 取消正在输入的章节名。
11. 中文输入法（微软拼音）在作品名、章节名、梗概与备注中组合输入正常，回车确认候选词时不会提前提交表单。

## M1-05 编辑器与自动保存

自动测试已覆盖：段落标识在拆分、合并、跨段删除、粘贴、移动、撤销重做下的继承（含随机编辑）；保存计划与版本守卫；自动保存的防抖、组合期间不保存、失败重试；草稿恢复；保存失败时复制与导出。以下依赖真实输入法与真实进程：

1. 输入法（微软拼音、搜狗拼音、五笔各一遍）：在段首、段尾、两段之间组合输入；组合中按回车选词，不应拆分段落；组合中状态栏不应出现“保存中”；组合结束约 1 秒后显示“已保存”。
2. 组合结束后按 Ctrl+Z、Ctrl+Y：撤销与重做以词为单位，文字与光标位置正确。
3. 连续输入一段长文字，停止后 2 秒内显示“已保存”（需求第八章“保存反馈”）。
4. 在段首回车插入空行、在段中回车拆分、在段首退格合并后切换章节再切回：文字与分段一致。
5. Ctrl+S 立即保存；状态栏的撤销、重做按钮可用。
6. 意外退出：输入一句后在 1 秒到 1.5 秒之间用任务管理器结束 `fudiao.exe`；重新打开作品与该章，显示“发现某时未保存的编辑”；“恢复这些编辑”后文字回来并自动保存；再次打开不再提示。“丢弃”后不再提示，文字为上次保存的内容。
7. 保存失败：打开作品后在资源管理器中把 `project.sqlite` 设为只读（或拔出作品所在的移动硬盘）；继续输入，状态栏显示“保存失败”与原因；“复制全文”后可粘贴到记事本；“导出本章”弹出保存对话框并写出 txt；此时切换章节被拦下并提示；关闭窗口第一次被拦下，第二次直接退出，重新打开后可从草稿恢复。
8. 粘贴从 Word 或网页复制的多段文字：按段落拆分，没有样式与图片。

## M1-06 章节快照

自动测试已覆盖：建立、列表、预览、恢复与再次恢复；恢复前快照；标识、顺序、版本、来源标记与事件关联；导出导入。以下在真实窗口中走一遍：

1. 写几段后“保存快照”，继续修改，打开“版本快照”：列表显示时间与“手动保存”，点击后右侧显示当时的正文、段数与字数。
2. “恢复到这个版本”→“确定恢复”：回到正文，内容为快照中的文字；列表新增一条“恢复前自动保存”，恢复它可以回到恢复前的文字。
3. 在输入法组合中途点“保存快照”：组合结束后才保存，快照内容包含组合结束后的文字。
4. 恢复后按 Ctrl+Z：撤销历史已清空，不会撤回到恢复前的内容（恢复前的内容在快照中）。

## M1-07 导入导出与备份

自动测试已覆盖：章节拆分规则与误判防护；编码识别（UTF-8、带 BOM、UTF-16、GB18030、Big5）；作品包条目校验与往返（逐表一致）；备份、自动备份保留 30 份、恢复与再次恢复；导入预览、导出与备份恢复的界面流程。以下在真实窗口中走一遍：

1. 导入一份 GBK 编码的网文 TXT（含“第X章”标题与全角缩进）：预览识别为 GBK，章节数与标题正确；改选 UTF-8 时出现乱码提示；导入后正文无乱码。
2. 导入 Markdown 文件：默认按 Markdown 标题拆分。
3. 导入 200 万字左右的 TXT：记录从点“导入”到目录出现的时间；导入后打开任意一章正常。
4. 导出整本 TXT 与 Markdown、导出 TXT（本章）：保存对话框默认文件名为作品名或章节名，用记事本打开无乱码。
5. 导出作品包后在作品列表“导入作品包”：成为一部新作品（文件夹名加序号），章节、正文、回收站与快照都在。
6. 备份与恢复：立即备份；改几章；恢复到该备份，目录与正文回到备份时；列表中出现“恢复前自动备份”，恢复它可以回到恢复前。
7. 关闭应用后在第二天（或把系统时间调后一天）打开作品：自动备份新增一份。
8. 恢复备份时有正在输入的章节：先保存再恢复，不丢已输入的文字（恢复前备份中可以找到）。

1. 用交互模式推演到出现待核实的裁决：“等你处理”里的理由、效果与发生的事读得懂；接受后继续推进。
2. 对一条裁决点“修改后确认”，把伤势改轻：确认后时间线里的局面按改过的来。
3. 在两个回合之间加入一件外部的事：下一回合里看得见、听得见的角色各自察觉到，其余角色没有。
4. 给一个角色加一条错误的认知，继续推进：他的行动是否受这条认知影响；别的角色所见里没有这条认知。
5. 展开“分支”，从“作者介入之前”分出新的推演：列表里多出一次标着“分支”的推演，原来那次的时间线不变。
6. 时间线里“提示”出现“缺少证据链”时，对照这个角色所见：他确实没有相关的观察或传闻。

## M4-06 回放与中断恢复

自动测试已覆盖：模型调用中途崩溃后继续（不重复调用、结果与不中断时一致）、关闭作品后重新打开继续、事件写完而运行记录未更新时列表按事件校正、校验回放（一致与被改动两种情况）。以下在真实窗口中走一遍（需要真实模型）：

1. 推演进行中，在任务管理器里结束应用进程；重新打开作品，“推演”里这次运行的回合与状态和关闭前一致，点“继续”接着推进，“用量与费用”里没有重复的调用。
2. 推演结束后点“校验回放”：提示各快照处重算的状态与当时记下的相同。
3. 断开网络后打开一次已经结束的推演：时间线、全局局面与角色所见照常显示（不需要模型）。

## M4-07 节拍表与写成正文

自动测试已覆盖：节拍表的材料只取视角角色在所选回合结束时的见闻、依据的记录、回合范围与角色的校验、修改节拍与文风、省略的节拍不进入请求、写成章末的候选稿与接受、空章节与已有正文的章节、未保存的修改、金丝雀（场景元信息、秘密、他人的角色卡、之后回合的见闻都不进入请求）、界面流程。以下在真实窗口中走一遍（需要真实模型，节拍表与正文合计约 5,000 到 15,000 输出 Token）：

1. 一次推演结束后，在“写成正文”里选一个角色与回合范围生成节拍表：每个节拍都是他亲眼看见、听到或别人对他说过的事，没有他不可能知道的事。
2. 把一个节拍改成“省略”、一个改成“倒叙”，填一句文风，保存后写到某一章末尾：任务页先后出现节拍表与推演写成正文；点“打开这一章看候选稿”看到候选稿。
3. 读候选稿：省略的那件事没有写；写到的都是视角角色当时知道的；没有出现另一个角色心里的盘算。
4. 采纳候选稿（步骤见 M4-08）：正文更新，来源色条为 AI，“版本快照”里有采纳前的快照。

## M4-08 采纳推演草案

自动测试已覆盖：采纳的准备（范围内的事、视角角色是否察觉、见闻、待复核的裁决、设定的对应）、未复核与未选事件时不写、一次写入正文与来源、故事事件与段落关联、事实及其来源事件、写入前快照、视角角色没有人物设定时不记认知、涉及锁定设定时须核对、过期时什么都不写、推演候选稿不能直接接受、界面流程。以下在真实窗口中走一遍（不调用模型，接着 M4-07 的候选稿）：

1. 在“设定”里建与场景角色同名的人物（例如视角角色），把其中一个锁定。
2. 在“AI 写作”里对推演写成的候选稿点“采纳…”：列出的事件里视角角色察觉到的已勾选，没察觉的标明；自动模式的运行有“已复核”的勾选项，全部勾上之前“采纳”不可点。
3. 勾一件事“同时记为世界事实”、勾两条见闻记为认知，点“采纳”：涉及锁定设定时提示核对；勾选“我已核对涉及锁定设定的内容”后采纳成功。
4. 正文更新，“版本快照”里有采纳前的快照；“事实”页出现已确认的世界事实与人物认知，锁定的设定没有变化。
5. 在采纳前先手动改一下这一章，再点“采纳”：提示候选稿已过期，事实页没有新增。
