# 作品库迁移

桌面端（Rust，编译期嵌入）与 Node 端（测试与 M0）共用本目录的迁移文件。

- 文件名为 `NNNN_名称.sql`（四位版本号，名称只用小写字母、数字与下划线），其他文件不是迁移。
- 按版本号顺序执行，每个文件在一个事务中执行，执行记录写入 `schema_migrations`。
- 已发布的迁移不得修改：校验和（统一换行符后的 SHA-256）不一致时拒绝打开作品库。需要改结构时新增一个迁移。
- 已有数据的库在执行迁移前，先用 `VACUUM INTO` 备份到项目文件夹的 `backups/`。
- 库的版本高于程序已知的最新迁移时拒绝打开，防止旧版程序写坏新版的库。
- 迁移中不要写不能在事务中执行的语句（例如 `PRAGMA journal_mode`、`VACUUM`）。
- 结构变更必须附带导出导入往返测试（AGENTS.md 硬性规则 20）。
- 每个迁移都要在 `src/data-export.ts` 的 `UPGRADES` 中登记导出数据的转换，较旧版本导出的作品包据此导入；只增加派生表的迁移登记为原样保留。
- 派生的表（索引及其影子表）列在 `src/schema.ts` 的 `DERIVED_TABLES`，不导出。
